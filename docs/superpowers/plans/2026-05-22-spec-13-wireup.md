# Spec 13 — Production Wire-up Plan (umbrella bead `glovebox-gdp4`)

Companion to `docs/superpowers/handoffs/2026-05-22-spec-13-testing.md`. That
handoff overstated completion — `internal/ingest/archives/` and `internal/ingest/auth/`
exist with tests, but `main.go` never constructs them, the config schema lacks
the matching sub-structs, the chart is missing PVC + deployment wiring, and
Vault has nothing in it. This plan closes those gaps.

## Phases

### Phase 1 — Config schema (Go)

Extend `internal/config/IngestConfig` so the chart's emitted
`ingest.auth` / `ingest.archives` JSON blocks no longer drop on the floor.

- [x] Add `AuthConfig` struct (vault addr, k8s role, KV mount + path,
  reload-interval, trusted-proxy CIDRs, per-IP + global rate-limit knobs).
- [x] Add `ArchivesConfig` struct (max upload size, concurrent caps,
  per-source + global hard-cap pcts, patch-idle timeout, cleanup
  intervals, done-retention).
- [x] JSON tags match the chart's `unset (deepCopy .Values.ingest.auth) "enabled"`
  output exactly.
- [x] Defaults match Helm values.yaml when the JSON block is absent.
- [x] Validation: when `ingest.enabled=true` AND `archives` is non-zero,
  fail fast on bad combinations (e.g. perSourceSoftCapPct outside 0–100,
  globalHardCapHysteresisPct > globalHardCapPct).
- [x] Tests in `config_test.go` for parse + defaults + validation.

### Phase 2 — `main.go` wire-up

Construct the spec 10 + spec 13 primitives and mount `/v1/archives*`.

- [x] Refactor inline mux into a shared `*http.ServeMux` so both
  `/v1/ingest` and `/v1/archives*` attach to the same listener on
  `cfg.Ingest.Port`.
- [x] When `cfg.Ingest.Archives.Enabled`:
  - [x] `auth.LoginK8s(cfg.Ingest.Auth.Vault.Addr, cfg.Ingest.Auth.Vault.K8sRole)`
  - [x] Build `auth.TokenStore`, `auth.RateLimiter`, `auth.ProxyResolver` from config.
  - [x] Build `archives.Telemetry` against the existing OTel provider.
  - [x] Build `archives.Store` with per-source + global concurrent caps.
  - [x] Compute PVC capacity via `syscall.Statfs(cfg.Ingest.Archives.StagingRoot)`
    (fallback to configured `pvcCapacityBytes` if statfs unsupported).
  - [x] Call `archives.StartArchiveListener` with the constructed
    `ArchiveListenerConfig`.
  - [x] On shutdown, ctx-cancel the goroutines (already wired via
    existing `cancel()`).
- [x] Tests: a `main_integration_test.go` that boots an in-process
  Glovebox against a fake Vault + temp staging root, asserts an
  HTTP POST to `/v1/archives` returns 401 without auth and 201 with.

  - [x] volume mounts: tmp-archives at `{{ .Values.ingest.archives.stagingRoot }}/.tmp-archives`,

### Phase 7 — Recognizer-team handoff deliverable

A single document under `docs/handoffs/recognizer-archive-delivery.md` that
the recognizer team can read (and that an LLM building the recognizer
client can parse) end-to-end without needing to read this plan, the spec,
or the chart. Must answer all four questions explicitly:

1. **Token acquisition** — the exact Vault path their source-id token
   lives at, the ESO `ExternalSecret` example that projects it into a
   K8s Secret in the `recognizer` namespace, and the SA token they need
   to mount so glovebox accepts their requests.
2. **Endpoint address** — the in-cluster URL
   (`http://glovebox.glovebox.svc.cluster.local:9091/v1/archives`), the
   port name (`ingest`), and the NetworkPolicy expectation (recognizer
   namespace must carry the `name: openclaw-recognizer` operator label).
3. **API contract** — concrete `curl` examples for the tus.io v1.0.0
   POST/PATCH/HEAD/DELETE flow, including the required `Upload-Metadata`
   keys (`archive_id`, `media_type`, `sha256`, `source_id`,
   `subtree_relative_path` for the google-takeout-subtree case), the
   four currently-accepted media types, and the wire-format spec
   pointer (spec 13 §4).
4. **Completion signal** — what (if anything) the recognizer must do
   beyond a successful PATCH-with-final-bytes to tell glovebox the
   archive is ready to scan. (Answer: nothing. The finalize step writes
   `archives/<id>/metadata.json` + `receipt.json` atomically; the spec
   9 watcher will pick the directory up from there. Document this so
   the recognizer team doesn't add a redundant ping/webhook.)

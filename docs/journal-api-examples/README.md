# Record journal API: golden answers

Answers of the real journal API (`internal/journal/httpapi`), generated by
`TestGoldenAnswers` (`internal/journal/httpapi/golden_test.go`) against a
real database. Consumers that cannot import `internal/journal/journalapi`
(openclaw's journal client) pin their decoders to these files: copy them,
note the glovebox commit they came from, and decode them strictly in a test,
so a change here shows up as a failing test rather than a silently dropped
field.

Regenerate (and check) with:

```bash
JOURNAL_PG_HOST_NETWORK=1 scripts/journal-test-db.sh ./internal/journal/httpapi/ -run TestGoldenAnswers -p 1 -update
```

Without `-update` the test fails on any difference. A change to these files
is a change to the wire contract: tell the consumers.

## The scenario

The connectors' real record types (the chart's `journal-record-types`
files), the fixture roster (`internal/journal/journaltest` `HouseholdV1`:
`e_parent1`, `e_parent2` guardians of siblings `e_child1`, `e_child2`, and a
guest), the spec's two attendance rules, and the gateway's policy entry as
gitops gives it (`read`, `counts`, `readers: "*"`). Three polls a day apart:

- a `course_mark` for each child; `e_child2`'s moves to another course
  section's scope on the second poll (`updated` with `prev_scope`);
- an `assignment` created unscored, scored on the second poll (`updated`,
  `score` from null), whose `description` the scanner withholds;
- three `attendance_mark` rows, two gone from the second complete snapshot
  (`removed`, `last_fields`), one of them back on the third (`restored`);
- a full-day `attendance_day` (rule `full_day_absence`: `importance`,
  `group_key`, `notify`);
- a `term_comment` whose audience widens from `[guardians]` to
  `[subject, guardians]` (the child's `updated` event shows the old value as
  `withheld: different audience`);
- two Schoology `lms_assignment` rows, one absent from the second
  (incomplete) listing (`in_latest_snapshot: false`, not removed), and an
  `lms_assignment_detail`.

Normalised: event sequence numbers are renumbered 1, 2, ... in the order the
journal assigned them, and `next` with them. Everything else is the answer
as served: every time is UTC (`...Z`) whatever the core's time zone, and the
test checks it (run it under a non-UTC `TZ`; `TestAnswersAreUTC` also swaps
the process's zone itself).
Values are placeholders.

## The files

| File | Request | HTTP status |
|---|---|---|
| `state-e_parent1.json` | `GET /v1/state?reader=e_parent1` | 200 |
| `state-e_parent1-include-removed.json` | `GET /v1/state?reader=e_parent1&include_removed=true` | 200 |
| `state-e_child1.json` | `GET /v1/state?reader=e_child1` | 200 |
| `events-e_parent1.json` | `GET /v1/events?reader=e_parent1&limit=1000` | 200 |
| `events-e_child1.json` | `GET /v1/events?reader=e_child1&limit=1000` | 200 |
| `events-empty.json` | `GET /v1/events?reader=e_parent1&after=<next>` | 200 |
| `counts-e_parent1.json` | `GET /v1/counts?reader=e_parent1` | 200 |
| `healthz.json` | `GET /v1/healthz` | 200 |
| `refusal-policy.json` | `GET /v1/state?reader=e_nobody` (not on the roster) | 403 |
| `refusal-bad-request.json` | `GET /v1/state?reader=e_child1&audience=guardians` | 400 |
| `refusal-unauthenticated.json` | `GET /v1/healthz` without a token | 401 (and `WWW-Authenticate: Bearer`) |
| `refusal-unavailable.json` | any request while the journal is not ready | 503, no `Retry-After` |

At its in-flight limit the journal answers the same `unavailable` shape with
a different `detail` and `Retry-After: 1`.

`household.json` is the fixture roster, byte for byte: its SHA-256 is the
`roster_sha256` of `healthz.json` and of the state answers (the journal
hashes the roster file's raw bytes).
